# Bid Workshop 使用手册

这是一份**照着做就行**的手册。每一步都写清楚了点哪里、应该看到什么。
不涉及改代码，也不假设你懂这个项目内部是怎么搭的。

---

## 0. 先看这 30 秒 —— 你多半卡在这里

如果你打开文件夹之后**找不到 Files 面板**，**不是你操作错了**。这个软件有三个反直觉的地方：

1. **侧边面板默认是关着的。**
2. **那个开关按钮，在你还没有开始任何一个会话之前是灰的、点不动。**
3. **`Files` 不是一个默认就有的标签 —— 它默认只开着 `Review`，你要自己用 `+` 把 `Files` 加出来。**

所以正确顺序是：

> 打开文件夹 → **在中间发一句话，开一个会话** → 右上角的侧面板按钮才会亮 → 打开它 → 用 `+` 把 `Files` 加出来 → 文件才列出来。

下面第 3～5 节就是这段话的详细版。

> 关于界面语言：最上面那条菜单栏是**英文**的（`File` / `Open Folder…` / `Save Document`），
> 界面里的按钮也大多是英文（`New thread` / `Files` / `Start thread`），
> 但**文档里的功能区别是中文**（`文件` / `开始` / `审阅`）。
> 这是现状，不是你的设置错了。

---

## 1. 打开它

在项目目录里执行：

```bash
./start-dev.sh
```

第一次会先构建一遍，慢一点，之后就是几十秒。窗口弹出来就成功了。

- 想关掉：直接关窗口，或者回终端按 `Ctrl+C`。
- 想在别人的机器上跑：把仓库复制过去，`pnpm install`，再 `./start-dev.sh`。不需要额外的服务、数据库、密钥。

---

## 2. 窗口里有什么

第一次打开是空的，只有中间一个 **`Open first folder`** 按钮。别急着点，先认清三个区域：

| 位置                 | 是什么                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------- |
| **左边一窄列**       | `New thread`、`Threads`、`Scheduled`、`Skills`、`Extensions`、`Settings`；你打开的文件夹会列在 `Threads` 底下 |
| **中间一大块**       | 平时是**对话**；一旦打开文档，就变成**文档**                                                                  |
| **右上角一个小图标** | 侧边面板的开关（鼠标停上去显示 `Show side panel`，快捷键 `⌘⌥B`）。**它现在是灰的**                            |

右边只有在你打开它之后才会出现一列 —— 那里才是 `Files` / `Review` / `Terminal` 住的地方。

---

## 3. 打开一个文件夹（工作区）

点中间那个 **`Open first folder`** 按钮（或者菜单 `File` → `Open Folder…`，`⌘O`）。

选中仓库里的这个目录：

```
workspaces/bid-sample
```

里面是准备好的样例数据：一份真实的投标文件 `.docx`、一份评审条件 `.md`。

选完之后你会看到：

- 左上角 `Threads` 底下多了一行 **`bid-sample`**
- 中间的按钮变成输入框，写着 `Ask pi anything…`，底下还有 `Local` `Worktree` 和模型名

**这时候你还是看不到任何文件。** 这是正常的 —— 下一步才是关键。

> 这个「文件夹」就是你的**工作区**。软件里的一切都围着它转：文件、AI 干活、评审，都是针对当前这个文件夹。

---

## 4. 先开一个会话（这一步不能跳）

在中间那个输入框里，随便打一句话，比如：

```
你好
```

然后点右边的发送按钮（或者按 `Enter`）。

会发生什么：

- 左边 `Threads` 底下出现一条会话记录
- 中间出现对话内容
- **右上角那个侧面板图标，现在亮了**

> 如果你还没配好模型，这句话会报错（红色的错误提示）。
> **没关系，会话已经建好了，后面的步骤照样能走。**
> 模型怎么配见第 11 节。

---

## 5. 打开 Files 面板（最关键的一步）

分两个动作：

1. **点右上角那个侧面板图标**（`Show side panel`，`⌘⌥B`）。
   右边会滑出一列，上面有个 **`Review`** 标签。
   注意：**只有 `Review`，没有 `Files`。**

2. **点标签栏右边的那个 `+` 号**（`Add tab`）。
   会弹出一个小面板，标题写着 **`Open a tool`**，里面有三个选项：

   | 选项       | 说明                           |
   | ---------- | ------------------------------ |
   | `Files`    | 浏览这个工作区里的文件         |
   | `Review`   | 看未提交的 / 分支的 / 本轮改动 |
   | `Terminal` | 在这个工作区里跑命令           |

   点 **`Files`**。

现在标签栏是 `Review` + `Files` 两个，`Files` 面板里列出了：

```
sample-bid.json
sample-response.json
投标文件-某软件科技.docx
评审条件.md
```

上面还有一条 `Filter files...` 可以过滤。到这一步，你才第一次看见工作区里的文件。

> **这一步只需要做一次**吗？不是 —— 面板的标签布局是**按「工作区 + 会话」保存**的。
> 换一个新会话，右边会回到默认状态（关着、而且只有 `Review`），还得再 `+` 一次。

---

## 6. 打开那份 Word 文档

在 `Files` 面板里点一下：

```
投标文件-某软件科技.docx
```

中间立刻变成文档视图 —— 页面、页边距、分页、页码都按真实排版渲染，不是「预览图」。

**这是打开文档唯一稳的路：文档得在当前工作区里，而且要从 `Files` 面板点。**
想开别处的文档，就用 `File` → `Open Folder…` 把它的文件夹打开，再照第 4、5 步来一遍。

> 两个容易踩的坑：
>
> - `⌘O` 是**打开文件夹**（`File` → `Open Folder…`），不是打开文档。
> - 软件一次只显示**一份**文档。换文档就再点一个文件。

---

## 7. 改一句话

1. 直接在页面上点进一行字，像用 Word 一样打字。
2. 改完存盘：`⌘S`，或者菜单 `File` → `Save Document`。
3. 想存成另一个文件：`⌘⇧S`（`File` → `Save Document As…`）。

**怎么确认真的存进去了**：切到别的文件再切回来，改动还在。
（真实情况是它已经写进磁盘上的那个 `.docx` 了 —— 用 Word 打开同一个文件也能看到。）

---

## 8. 留下审阅痕迹 —— 这是这个软件存在的理由

在文档功能区点 **`审阅`** 标签（在 `开始` / `插入` 后面那一排）。这一页里有三类东西：

**修订**
点一下「修订」就打开了记录。之后你做的每一处改动都会变成修订：

- 插入的文字带下划线
- 删除的文字带删除线

**批注**
先**用鼠标选中一句话**，再点「新建批注」。选中的那句话就是批注挂靠的位置。

**接受 / 拒绝**
可以一条一条来（「接受此修订」「拒绝此修订」），也可以「接受所有修订」「拒绝所有修订」。

**关键一点：这些东西不是画在屏幕上的。**
存盘之后，批注和修订是**真的写进那份 `.docx` 文件**里的。用 Word 打开同一份文件，
批注还在、修订还在、作者也在。这才是「交出去」的前提。

---

## 9. 把它交出去

- **导出 PDF** / **导出 HTML**：文档界面里可以导出成文件，导出的是你看到的排版。
- **打印**：**不支持**。这台机器上没接系统打印。
- **把好几份 PDF 合成一份**：**不支持**，仓库里没引入 PDF 相关的库。

导出完的文件在哪，界面会告诉你路径。

---

## 10. 从零写一份新文档

菜单 `File` → `New Document`（快捷键 `⌘⌥N`）。

它会把当前视图**清成一张白纸**（不是新开一个窗口），你直接开始写就行。
写完 `⌘S`，会问你要存到哪儿。

---

## 11. 让 AI 干活 —— 有两条路，别混

这个软件里有**两套** AI 入口，能力不一样，我先说清楚再让你用。

### 11.1 壳自己的 AI（中间那块对话）

就是你平时打字的地方。你直接说人话：

> 读一下 `投标文件-某软件科技.docx`，把第 12 段的金额改成 30 万

它会**真的去改磁盘上的那个文件**。它手上有四个文档工具：

| 工具           | 干什么                             |
| -------------- | ---------------------------------- |
| `read_docx`    | 读一份 `.docx`，把段落按编号列出来 |
| `create_docx`  | 从零写一份新的 `.docx`             |
| `update_docx`  | 改某一段、或者在某个位置插一段     |
| `comment_docx` | 给某一段（或者段里的某句话）加批注 |

你不需要记这些名字，直接提要求就行；它自己会挑。

前提：**得先有工作区和会话**（第 3、4 步），因为工具说的是「相对于这条会话的文件夹」。
另外，这条路要真的跑起来，模型得先配好（见 11.3）。

### 11.2 文档里自带的 AI 面板（文档右侧那一栏）

打开文档后，右边会有一栏 AI 面板（在最右边，可以把侧边面板先收起来给它让地方）。它跟上面那套是**两回事**：

- 它专门改**你正在看的这份文档**：插入、替换、加批注、接受/拒绝修订，都在编辑器里实时发生。
- 它用的也是**你在 pi 里配好的模型** —— 一个软件只有一处配模型的地方，这里不用再配一遍。
- 如果还没配过模型，你发一句话，它会**明确报错**告诉你没有配置 AI 服务
  （原文是一句英文：`No AI provider is configured for this app yet.`），
  不会假装转圈、也不会让你以为是自己操作错了。

文档里还有些一键的 AI 动作，比如「AI 总结修订」「AI 处理批注」，就在 `审阅` 那一页里，
把一批修订或批注丢给它总结/处理。

### 11.3 模型在哪配

一个地方：pi 的配置，也就是 `~/.pi/agent/models.json`。
配好之后，上面两套 AI **都**会用它。

## 12. 遇到这些，别慌

| 现象                               | 其实是什么                                    |
| ---------------------------------- | --------------------------------------------- |
| 找不到 `Files` 面板                | 面板默认关着，而且要先开会话（第 4、5 步）    |
| 右上角侧面板图标是灰的、点不动     | 还没有会话。先在中间发一句话（第 4 步）       |
| 侧面板开了，但只有 `Review`        | `Files` 要自己用 `+` 加出来（第 5 步）        |
| 发了一句话就报红色错误             | 模型没配好。仍然不影响建会话、开 Files 面板   |
| `⌘O` 打开了选文件夹                | 对，它就是打开文件夹，不是打开文档            |
| AI 说「还没有配置 AI 服务」        | 模型没配。配好 `~/.pi/agent/models.json` 再试 |
| 想打印                             | 不支持                                        |
| 想合并 PDF、想从磁盘挑一张图插进来 | 不支持                                        |
| 一次只能看一份文档                 | 一窗一份，这是当前的设计                      |

## 13. 一轮完整的演示（照着走一遍就懂了）

1. `./start-dev.sh`，等窗口出来。
2. 点 **`Open first folder`**，选 `workspaces/bid-sample`。
3. 在中间的输入框里打「你好」并发送 —— **这一步是为了让会话存在**。
4. 点右上角的侧面板图标，然后点 `+`，选 **`Files`**。
5. 在 `Files` 里点 `投标文件-某软件科技.docx`，中间出现文档。
6. 点 `审阅` → 打开「修订」→ 在正文里改一句话 → `⌘S`。
7. 还是 `审阅` 页 → 选中一句话 → 「新建批注」→ 写上你想说的话 → `⌘S`。
8. 导出一次 PDF，看导出的排版对不对。
9. 在中间跟壳的 AI 说：
   「读一下 `投标文件-某软件科技.docx`，告诉我它一共有几段，第 3 段写了什么。」
10. 在文档右侧的 AI 面板里问一句关于这份文档的话（前提是模型配好了）。
11. 关掉窗口，或者终端 `Ctrl+C`。

走完这一遍，你就把这个壳**现在真正会做的事**都摸过一遍了。
