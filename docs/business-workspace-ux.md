## 1. 成果定义

### 1.1 L1 产品级成果（一句话）

**一个人打开这个软件，能把一份投标文件从头审到尾**：软件按你选的维度和判据逐条核对，把意见写进 Word 批注，同时出一张 HTML 核对表；你逐条决定采纳或驳回，改完再跑一轮，每轮留下一个带版本号的文档。

## 2. 全局公司资料库（新面）

用户的要求：公司资料**不该散在每个工作空间里**，应该有一个全局的地儿存，建工作空间时**引用**过来。

- **位置**：应用级（`userData` 下），**不属于任何工作空间**，不进任何工作区的 git。
- **形态**：一个目录 + 一份清单（索引）。清单里按类目组织：公司基本情况、人员、资质证书、类似业绩、财务、其他。每条资料记：名称、类目、文件、来源、更新时间、**是否必备**。
- **维护**：在"资料库"管理面里维护（新增/替换/退役）。工作空间侧**只读**。
- **引用进来怎么落地**：
  - 工作空间档案里记引用条目（`references: [{ libraryId, path, ... }]`），工作空间内**不复制字节**；
  - 目录呈现用符号链接（symlink）——这是"引用"的字面实现；
  - **风险**：symlink 在 Windows / 网络盘 / 备份工具下行为不一致。降级方案：symlink 不可用时改用"虚拟引用"（不落链接，只在软件里以只读清单呈现，读写都走软件通道）。**这条要在实现前验证，见 §9。**
- **为什么重要**：公司资料是"一改处处生效"的东西（资质更新一次，所有在跑的工作空间都该看到新版），拷贝会把版本分叉。

## 4. 版本命名与版本链（UD6 的细节）

```
产出物/
  投标文件.docx          ← 用户放入的原稿（软件不改它）
  投标文件-v1.docx       ← 第一轮产出：带批注
  投标文件-v2.docx       ← 第二轮产出：输入是 v1，带新的批注
  投标文件-定稿.docx      ← 用户确认后的交付件
反馈/
  核对表-v1.html          ← 第一轮的 HTML 表格
  核对表-v2.html          ← 第二轮的（可含与上一轮的差异列）
```

规则：

1. **原稿永不修改**（沿用设计决策 D3）。"原地写回"是可选项，不在这条主链路上。
2. `vN` 的输入 = `v(N-1)`（`v1` 的输入 = 原稿）；每轮产出新文件，不覆盖旧版本。
3. 版本号只由软件递增，不让用户手填；用户改名后以文件名识别失败时，回退到台账里的版本记录而不是猜。
4. 版本链要记录在台账里（`runId → document → version → 输入版本`），否则"哪一轮基于哪一版"无法追。

## 5. 界面骨架

主面板仍然是**会话优先**（既有纪律，不改）。用户看到的面：

| 区域             | 内容                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------- |
| 左：工作空间导航 | 工作空间列表（既有）、当前工作空间下的文档与分区、入口（新建工作空间 / 打开目录）       |
| 中：会话         | 对话、问答卡片、目标声明                                                                |
| 右：侧栏工具区   | Files（文档 tab）、扩展视图（审查条目面板、文档视图）；内置 AI 面板**默认隐藏**（T-28） |
| 上下文条         | 当前工作空间 / 业务类型 / 目标 / 当前轮次 / 处置进度 / 定稿入口                         |

状态与空态清单（每个都要有明确文案，不能白屏）：

- 空工作空间 / 无待审文件 / 资料库为空 / 资料缺失 / 审到一半用户取消 / 批注无法锚定（表格）/ 引擎解析失败 / 只读区被尝试写入 / 判据文件缺失。

## 6. 失败与降级路径（一览）

| 情况           | 软件行为                                                           |
| -------------- | ------------------------------------------------------------------ |
| 资料缺失       | 不阻断；相关判据变成"无法核对"并单列                               |
| 判据文件缺失   | 用业务包内置判据兜底，并**显式说明用的是内置判据**（不是静默替换） |
| 表格内无法锚定 | 落到表标题段落 + 显式标注未锚定                                    |
| 文档解析失败   | 明确报错，不产出半成品；原稿不动                                   |
| 用户中途取消   | 保留已完成的部分（台账不丢），明确标"未完成"                       |
| symlink 不可用 | 降级为虚拟引用（见 §2），并告知用户为什么                          |
| 远端判据       | 本轮不做；界面显示"判据来源：本地"，字段留给未来                   |
